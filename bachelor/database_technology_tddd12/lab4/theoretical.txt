9. Open two MySQL sessions. We call one of them A and the other one B. Write
START TRANSACTION; in both terminals.
a) In session A, add a new reservation.
b) Is this reservation visible in session B? Why? Why not?

    - ANSWER:
            - No, this is because of the atomicity property of a transaction which means
            - a transaction is not complete until it is committed. In this case the modification
            - which takes place in session A is not cimmitted and therefor is not observed in 
            - session B.

c) What happens if you try to modify the reservation from A in B? Explain what
happens and why this happens and how this relates to the concept of isolation
of transactions.

    - ANSWER:
        - In order to modify the reservation made in session A from session B the transactions
        - must have been completed in both the sessions. If the modification is done before the 
        - commit command the reservation table will be uppdated according to the latest committed
        - session. This is due to isolation property of transations, which means that even though 
        - two transations are happening at the same time it should appear that the execution is
        - in isolation.
